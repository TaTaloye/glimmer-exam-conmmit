## 问题 1：常见面板及其作用

| 面板 | 可以用来做什么 |
| --- | --- |
| Elements（元素） | 查看浏览器当前的 DOM 结构，HTML 和 CSS |
| Console（控制台） | 查看脚本输出的日志、警告和报错，也能执行 JavaScript 表达式 |
| Sources（源代码） | 查看加载的脚本，设置断点，逐步执行 JavaScript 并观察变量 |
| Network（网络） | 查看页面加载时的请求，包括地址、方法、状态码、请求头、响应内容和耗时 |
| Application（应用程序） | 查看当前网站的 Cookie、Local Storage等数据 |
| Performance（性能） | 记录页面运行过程，分析脚本执行、布局和绘制的耗时，排查卡顿|
| Memory（内存） | 检查内存占用，分析对象是否被持续保留，帮助排查内存泄漏 |

最有用的肯定是元素面板啊，直接可以看其他人的往咱的源代码了

## 问题 2：临时修改网页，刷新后会怎样？

### 2.1 面板修改

现象：修改后，页面马上显示新文字；刷新后，恢复 HTML 源文件里的文字

### 2.2 为什么刷新后会恢复
：豆包豆包，为什么刷新后会修复？
：浏览器读取 HTML 后，会建立 DOM，也就是网页在浏览器中的节点结构。Elements 展示的正是这份结构，改动其中的文字会直接反映到页面上
这次改动没有保存到 `demo.html`。刷新时，浏览器重新读取源文件并构建页面，旧文字也就回来了

## 问题 3：Cookie 是什么？

Cookie是浏览器保存的一小段网站数据，在满足域名、路径、安全属性等条件时，浏览器会把它随http请求发送给网站。网站可以据此识别会话，让用户刷新页面后仍保持登录，也能保存偏好设置等信息。

详情：[MDN：HTTP Cookie](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/Cookies)

## 问题 4：Network

### GET和POST

通常刷新一个普通网页时，GET 比较多，
因为 HTML、CSS、JS图片和字体大多通过 GET 获取
登录提交、表单提交或部分接口则可能使用 POST，但不能把“接口请求”全部当成 POST。

### 200和404

| 状态码 | 含义 |
| --- | --- |
| `200 OK` | 请求成功。对于常见 GET 请求，响应通常包含所请求的资源内容|
| `404 Not Found` | 服务器没有找到请求的资源|
